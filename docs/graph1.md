LangGraph 的核心能力可以概括为：**用状态图来编排复杂的 AI Agent 工作流**，让 Agent 的执行路径、状态变化、循环调用、人工干预和持久化运行都能被显式地定义和管理。

它的核心能力主要有这些：

### 1. 图结构编排复杂工作流

LangGraph 把 Agent 的执行过程建模成一张**有向图**：  
- **节点 Node**：执行具体动作，比如调用 LLM、查询数据库、调用工具、处理数据。  
- **边 Edge**：决定节点之间如何流转。  
- **条件边**：根据当前状态决定下一步走哪条路径。

相比简单的线性 Chain，它更适合表达“根据结果决定下一步”的动态流程。

### 2. 支持循环与动态分支

传统工作流很多是 DAG，即有向无环图；但 LangGraph 支持**有环图**，所以可以处理需要反复执行的任务，例如：

- 多轮工具调用；
- Agent 自我修正；
- 多次检索后再回答；
- 循环检查任务是否完成；
- 根据中间结果重新规划。

这让 Agent 不只是“执行一次”，而是可以“思考—执行—反馈—再思考”。

### 3. 显式状态管理

LangGraph 维护一个**中央状态对象**，所有节点都可以读取和更新它。  
状态通常用来保存：

- 用户输入；
- 历史消息；
- 工具调用结果；
- 当前执行计划；
- 中间变量；
- 任务完成标志。

状态可以定义为 `TypedDict`、Pydantic 模型等，并支持多个节点并发写入时的合并策略。

### 4. 多 Agent 协作

LangGraph 适合把复杂任务拆成多个子 Agent 或子模块，比如：

- 一个节点负责规划；
- 一个节点负责搜索；
- 一个节点负责代码生成；
- 一个节点负责审核；
- 一个节点负责输出最终结果。

它支持多智能体并行、异步协作和模块化子图，便于构建分工明确的 Agent 系统。

### 5. 人机协同

LangGraph 支持 **Human-in-the-Loop**，可以在执行过程中加入人工确认、审核或干预。  
典型场景包括：

- 敏感操作前让人确认；
- 审核 Agent 生成的计划；
- 人工修改中间状态；
- 审批后继续执行后续节点。

### 6. 持久化与断点恢复

LangGraph 支持检查点和持久化执行，任务中断后可以恢复。  
例如：

- 服务重启后继续执行；
- 长时间任务不会丢失上下文；
- 人工审核后再从断点继续；
- 长对话或长流程任务保持状态一致。

### 7. 可观测、可调试、可部署

LangGraph 可以与 LangSmith 等工具配合，追踪执行路径、状态变化和节点输出。  
它还提供 CLI 和部署能力，适合把 Agent 工作流投入生产环境。

简单理解：  
**LangChain 更擅长提供模型、工具、组件；LangGraph 更擅长编排这些组件如何按图执行。** 如果你要做一个需要循环、分支、状态保持、多 Agent 协作或人工审核的 Agent 系统，LangGraph 会比单纯线性链式调用更合适。
