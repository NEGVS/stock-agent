## 三、问题分析

### 1. 致命问题：网络请求失败（直接原因）

完整报错是 `ProxyError`：

```
ProxyError: HTTPSConnectionPool(host='82.push2.eastmoney.com', port=443)
Max retries exceeded ... url: /api/qt/clist/get
```

`akshare` 通过 eastmoney 接口取全市场快照。机器上系统代理是开着的：

```
scutil --proxy →  HTTPProxy 127.0.0.1:7890  (HTTP/HTTPS/SOCKS 全是 7890)
```

`requests` 自动读取系统代理，所有请求被塞给 `127.0.0.1:7890`，但该端口**没有服务在监听**（代理软件没开），连接被拒。

实测三种情况：

| 方式 | 结果 |
|---|---|
| 走系统代理 | `ProxyError` — 端口不通 |
| `curl --noproxy '*'`（绕过代理） | `Empty reply from server`（curl:52）— TCP 通、TLS 被重置 |
| ping/TCP 到 eastmoney | DNS + 连通性正常（`push2ipv6.trafficmanager.cn`，11ms） |

第二条说明还有第二层问题：即使绕过代理，直连也被 RST，这是境外出口时的典型现象。

**解法**：先打开代理软件让 7890 端口起来，再跑一次。若仍失败，则是代理规则把 eastmoney 分到了直连，需在规则里让它走代理。

### 2. 代码问题：`planner` 有两条出边，语义冲突

`graph.py:58` 有：

```python
builder.add_edge("planner", END)
```

同时又 `add_conditional_edges("planner", route_after_planner)`。同一节点既是条件边源、又有无条件边，是打架的。当前之所以没报错，是因为条件路由先返回了 `"market"`；但 LangGraph 会把 planner 的出口算作两个，一旦路由判定走到 END 分支，`market`/`technical` 就永远不会执行。

### 3. State 定义与使用不一致

- `app/state.py` 里 `StockState` 把 `news / technical / fund / risk / summary / market_data` 都声明成**必填**（无 `Optional`、无默认值），但 planner 阶段根本没有这些字段。
- `technical` 这个 key 是字符串，与 `technical` 节点函数名撞车。
- `app/models/state.py` 是空文件，与 `app/state.py` 重复。
- `app/state.py:18` 的 `market_data` 声明为必填 `dict`。

### 4. 工具函数本身的健壮性

- `stock_tool.py` 每次都拉**全市场**快照再本地过滤，几千行，慢且没必要；
- 返回的 `code` 是 `000000` 格式，后续接 K 线/财务接口还需补市场前缀；
- **没有异常处理**——一次网络抖动就让整张图崩掉。

## 四、优化实施记录

### 4.1 新增 `app/utils/network.py` — 显式控制代理

macOS 的系统代理会被 `requests` 静默继承，这是本次报错的根因。新模块把代理来源收敛为一处，优先级：

```
环境变量 HTTP_PROXY / HTTPS_PROXY  >  .env 的 STOCK_PROXY  >  直连
```

即**默认直连**，不再被系统代理劫持。`setup_proxy()` 必须在 `import akshare` 之前调用，否则底层连接池已按旧配置建好。

### 4.2 重写 `app/tools/stock_tool.py` — 分层 + 降级

拆成三个函数，职责单一：

| 函数 | 职责 |
|---|---|
| `fetch_spot_snapshot()` | 只负责拉全市场快照，带 3 次重试；全失败返回 `None` |
| `get_stock_info()` | 优先走 `stock_individual_info_em`（只取一行，比拉全市场快两个数量级），失败再降级到全市场过滤 |
| `_latest_price()` | 详情接口不带实时价，单独查一次 |

关键改动：**任何失败都返回 `{"found": False, "message": ...}`，不抛异常**。字段映射抽成 `_FIELD_MAP` 常量，返回结构从 5 个字段扩到 8 个（补 `change_pct / amount / market_cap / pe / industry`）。

### 4.3 `app/graph/graph.py` — 删除冲突边

删掉 `builder.add_edge("planner", END)`，planner 的出口只由条件边决定。同时在代码里留了注释说明**为什么不能加**，避免以后又被加回去。`route_after_planner` 的日志也改了：原先把收到的 `state` 打印成"返回值"，实际返回的是字符串，现在两者分开打印。

### 4.4 `app/state.py` — 全部改为可缺省

```python
class StockState(TypedDict, total=False):
    ...
```

图是一步步往下走的，planner 阶段没有 `market_data`、market 阶段没有 `summary`，写必填只会让类型提示失真。同时删除了重复的空文件 `app/models/state.py`。

### 4.5 节点改为返回增量更新

各节点不再 `state["x"] = ...; return state`（原地改再返回全量），而是 `return {"x": ...}`——LangGraph 会做增量合并。这符合官方写法，也让"谁改了哪个字段"更清晰。

### 4.6 `app/agents/planner.py` — 抽出 `extract_stock()`

旧的硬编码 `if "信维" in question` 换成可复用的抽取函数，后续接 LLM 做实体识别只需替换这一个函数。

过程中发现一个**新问题**：只做"剥噪声"会把「你好」解析成股票名（剥完剩「你好」，3 个汉字，直接进 market）。于是补了形态校验 `^[一-龥A-Za-z]{3,8}$`。

测试结果：

| 输入 | 输出 |
|---|---|
| `分析信维通信` | `信维通信` |
| `帮我看看信维通信` | `信维通信` |
| `分析一下信维通信的股票` | `信维通信` |
| `你好` / `在吗` / `""` | `None` |
| `分析贵州茅台` | `贵州茅台` |
| `今天天气怎么样` | `今天天气` ← **仍会误判** |

最后一行是已知局限：`今天天气` 剥掉「怎么样」后剩 4 个汉字，形态上合法。要根治得靠真股票名清单或 LLM 实体识别，形态规则只能挡住一部分。

### 4.8 新增 `.gitignore`，清理误提交的产物

仓库原先没有 `.gitignore`，把编译产物、IDE 配置和日志都提交了进去：

| 类别 | 被跟踪的文件 |
|---|---|
| 字节码 | `__pycache__/*.pyc` × 7 |
| macOS | `.DS_Store`、`app/.DS_Store` |
| 日志 | `log.log`、`app/docs/log/doubaolog.log` |
| IDE | `.idea/` 下 9 个文件 |

新增 `.gitignore` 覆盖 Python / 虚拟环境 / 构建产物 / 测试缓存 / IDE / macOS / 日志与 `.env`，然后用 `git rm -r --cached` 把这些文件移出索引——**只从 git 移除，本地文件原样保留**（已用 `ls` 和 `git check-ignore -v` 双重确认）。

已提交过的文件 `.gitignore` 管不住，必须显式 `--cached` 移除，这是两步操作而不是一步。

### 4.9 同步 `app/main.py` 的流程图注释

原注释画的是「planner → END」，与当前链路脱节。更新为实际链路（含 ask_user 分支），并把「为什么不能给 planner 加无条件边」的警告一并写进注释。

### 4.10 一个坑：不要用 `draw_mermaid()` 检查边

`graph.get_graph().draw_mermaid()` 输出里显示 `planner --> __end__`，看起来像是条件边没生效。实际是 **LangGraph 渲染条件边的方式**——多出口时它只画一条到 END，不会画出每个分支。判定依据应该是运行时行为，而非这张图。
