## 三、问题分析

### 1. 致命问题：网络请求失败（直接原因）

完整报错是 `ProxyError`：

```
ProxyError: HTTPSConnectionPool(host='82.push2.eastmoney.com', port=443)
Max retries exceeded ... url: /api/qt/clist/get
```

`akshare` 通过 eastmoney 接口取全市场快照。机器上系统代理是开着的：

```
scutil --proxy →  HTTPProxy 127.0.0.1:7890  (HTTP/HTTPS/SOCKS 全是 7890)
```

`requests` 自动读取系统代理，所有请求被塞给 `127.0.0.1:7890`，但该端口**没有服务在监听**（代理软件没开），连接被拒。

实测三种情况：

| 方式 | 结果 |
|---|---|
| 走系统代理 | `ProxyError` — 端口不通 |
| `curl --noproxy '*'`（绕过代理） | `Empty reply from server`（curl:52）— TCP 通、TLS 被重置 |
| ping/TCP 到 eastmoney | DNS + 连通性正常（`push2ipv6.trafficmanager.cn`，11ms） |

第二条说明还有第二层问题：即使绕过代理，直连也被 RST，这是境外出口时的典型现象。

**解法**：先打开代理软件让 7890 端口起来，再跑一次。若仍失败，则是代理规则把 eastmoney 分到了直连，需在规则里让它走代理。

### 2. 代码问题：`planner` 有两条出边，语义冲突

`graph.py:58` 有：

```python
builder.add_edge("planner", END)
```

同时又 `add_conditional_edges("planner", route_after_planner)`。同一节点既是条件边源、又有无条件边，是打架的。当前之所以没报错，是因为条件路由先返回了 `"market"`；但 LangGraph 会把 planner 的出口算作两个，一旦路由判定走到 END 分支，`market`/`technical` 就永远不会执行。

### 3. State 定义与使用不一致

- `app/state.py` 里 `StockState` 把 `news / technical / fund / risk / summary / market_data` 都声明成**必填**（无 `Optional`、无默认值），但 planner 阶段根本没有这些字段。
- `technical` 这个 key 是字符串，与 `technical` 节点函数名撞车。
- `app/models/state.py` 是空文件，与 `app/state.py` 重复。
- `app/state.py:18` 的 `market_data` 声明为必填 `dict`。

### 4. 工具函数本身的健壮性

- `stock_tool.py` 每次都拉**全市场**快照再本地过滤，几千行，慢且没必要；
- 返回的 `code` 是 `000000` 格式，后续接 K 线/财务接口还需补市场前缀；
- **没有异常处理**——一次网络抖动就让整张图崩掉。

## 四、优化实施记录

### 4.1 新增 `app/utils/network.py` — 显式控制代理

macOS 的系统代理会被 `requests` 静默继承，这是本次报错的根因。新模块把代理来源收敛为一处，优先级：

```
环境变量 HTTP_PROXY / HTTPS_PROXY  >  .env 的 STOCK_PROXY  >  直连
```

即**默认直连**，不再被系统代理劫持。`setup_proxy()` 必须在 `import akshare` 之前调用，否则底层连接池已按旧配置建好。

### 4.2 重写 `app/tools/stock_tool.py` — 分层 + 降级

拆成三个函数，职责单一：

| 函数 | 职责 |
|---|---|
| `fetch_spot_snapshot()` | 只负责拉全市场快照，带 3 次重试；全失败返回 `None` |
| `get_stock_info()` | 优先走 `stock_individual_info_em`（只取一行，比拉全市场快两个数量级），失败再降级到全市场过滤 |
| `_latest_price()` | 详情接口不带实时价，单独查一次 |

关键改动：**任何失败都返回 `{"found": False, "message": ...}`，不抛异常**。字段映射抽成 `_FIELD_MAP` 常量，返回结构从 5 个字段扩到 8 个（补 `change_pct / amount / market_cap / pe / industry`）。

### 4.3 `app/graph/graph.py` — 删除冲突边

删掉 `builder.add_edge("planner", END)`，planner 的出口只由条件边决定。同时在代码里留了注释说明**为什么不能加**，避免以后又被加回去。`route_after_planner` 的日志也改了：原先把收到的 `state` 打印成"返回值"，实际返回的是字符串，现在两者分开打印。

### 4.4 `app/state.py` — 全部改为可缺省

```python

    ...
```

图是一步步往下走的，planner 阶段没有 `market_data`、market 阶段没有 `summary`，写必填只会让类型提示失真。同时删除了重复的空文件 `app/models/state.py`。

### 4.5 节点改为返回增量更新

各节点不再 `state["x"] = ...; return state`（原地改再返回全量），而是 `return {"x": ...}`——LangGraph 会做增量合并。这符合官方写法，也让"谁改了哪个字段"更清晰。

### 4.6 `app/agents/planner.py` — 抽出 `extract_stock()`

旧的硬编码 `if "信维" in question` 换成可复用的抽取函数，后续接 LLM 做实体识别只需替换这一个函数。

## 六、第二轮：网络问题的真正根因与多源降级

第一轮把 `ProxyError` 修成了 `RemoteDisconnected`（代理不再被系统设置劫持），但取数仍然失败。这一轮挖到了底。

### 6.1 排查过程

先说结论：**`RemoteDisconnected` 不是代码问题，是 eastmoney 的 `push2` 实时接口在当前网络下不可达。**

逐层排查记录：

| 步骤 | 观察 | 结论 |
|---|---|---|
| `setup_proxy()` 返回 | `None`（`.env` 未配，走直连） | 代理配置本身生效了 |
| `nc -z 127.0.0.1 7890` | 可连接 | 代理软件在跑 |
| curl 直连带 UA | **200** | 目标站点本身可直连 |
| requests 强制直连 | `RemoteDisconnected` | ⚠️ 与 curl 矛盾 |
| 清空所有 `*proxy*` 环境变量后 `getproxies()` | 仍是 `127.0.0.1:7890` | requests 读的是 **macOS 系统代理 scutil**，不是环境变量 |
| 本地起假代理抓包 | urllib3 发出 `CONNECT host:443 HTTP/1.0\r\n\r\n` | **无 `Host` 头、HTTP/1.0** |
| 同样抓 curl | `CONNECT ... HTTP/1.1` + `Host` + `User-Agent` | 代理能据此做域名判定 |

**关键发现**：urllib3 发的裸 `HTTP/1.0` CONNECT 报文缺少 `Host` 头，代理软件判定不出目标就掐断连接，表现为 `ProxyError: Unable to connect to proxy`。这不是「端口不通」，而容易被误读成代理没开。

### 6.2 但换成 SOCKS5 后仍然失败——真正的原因

既然 HTTP CONNECT 有报文问题，改测 SOCKS5：

- `requests` + `socks5h://` → `RemoteDisconnected`（不再是 ProxyError，进了一步）
- `akshare` + `socks5h://` → 同样 `RemoteDisconnected`
- **curl（HTTP 代理 / SOCKS5 / 直连）三者全部 `Empty reply`**

三条路径全挂在同一处，说明与客户端实现无关。继续按域名/接口拆分：

| 目标 | 结果 |
|---|---|
| `push2.eastmoney.com/api/qt/clist/get` | ❌ 000 空响应 |
| `push2his.eastmoney.com/api/qt/stock/kline/get` | ✅ 200 |
| `push2his.eastmoney.com/api/qt/clist/get` | ❌ 000 |
| `quote.eastmoney.com` | ✅ 200 |
| `qt.gtimg.cn`（腾讯） | ✅ 200 |
| `hq.sinajs.cn`（新浪） | ✅ 200 |

**被阻断的是 `/api/qt/clist/get` 这个实时列表接口，不是域名。** 而它正是 `ak.stock_zh_a_spot_em()` 的唯一数据源——所以那个函数在当前网络下必然失败，换代理也没用。

验证各数据源可用性：

| akshare 函数 | 底层源 | 结果 |
|---|---|---|
| `stock_zh_a_hist` | push2his | ✅ 181 行 |
| `stock_zh_a_spot` | 新浪 | ✅ **5568 行** |
| `stock_individual_info_em` | push2 | ❌ |
| `stock_bid_ask_em` | push2 | ❌ |
| `stock_zh_a_spot_em` | push2 | ❌ |

### 6.3 改造：东财 → 新浪自动降级

`app/tools/stock_tool.py` 重写为多源结构：

```python

    ("eastmoney", _fetch_eastmoney, _EM_FIELD_MAP),   # 快，但可能被阻断
```

`fetch_spot_snapshot()` 按顺序降级，并加了两层优化：

| 机制 | 作用 |

## 七、第三轮：接入 akshare_proxy_patch，东财接口恢复

### 7.1 问题回顾

第二轮结论是「`/api/qt/clist/get` 被阻断，代码侧无解，只能降级到新浪」。现在换了个解法：用 `akshare-proxy-patch` 走第三方网关解除封控。

### 7.2 要点：调用时机必须在 `import akshare` 之前

插件文档反复强调：

> 重要：插件引入和调用一定要放到最顶部！不能在 akshare 或 efinance 之后引入！

原因是 akshare 在 import 时就会建立连接池，补丁晚于这一刻装，hook 覆盖不到已创建的连接。

靠开发者在每个文件里手动注意不可靠——**任何一处忘记，补丁就会静默失效**，而且不报错，只是又降级回了新浪源。所以做成机制保证：

```
app/__init__.py                    ← Python 保证包导入时先执行
    └── bootstrap()
            ├── setup_proxy()      ① 先配代理
            └── install_patch()    ② 再装补丁
                    └── import akshare   ③ 最后才 import
```

`app/__init__.py` 是 Python 里最早的执行时机，任何 `from app.xxx import ...` 都会先触发它。这样就不用依赖"记得放最顶部"。

### 7.3 实现：`app/utils/bootstrap.py`

文档给的是硬编码写法：

```python
akshare_proxy_patch.install_patch("101.201.173.125", auth_token="你的TOKEN", ...)
```

但 **token 不该进代码**。改成从 `.env` 读取，并加了几个保护：

| 设计 | 原因 |
|---|---|
| token 走 `.env` | 凭证不进版本库 |
| 未配置 token 时跳过而非报错 | 没 token 也能跑，只是走降级路径 |
| `ImportError` 捕获 | 插件没装时不影响启动 |
| `_installed` 标志 | 模块可能被重复导入，补丁只该装一次 |
| `fast` / `retry` 可配 | 便于按需调参 |

`hook_domains` 用文档给的完整列表（含补充的 `searchapi` 和 `push2delay` 两条）。

### 7.5 顺带发现：两个源的成交量单位差 100 倍

切回东财后暴露一个隐患：

| 源 | 成交量 | 单位 |
|---|---|---|
| 东财 | `433732.0` | 手 |
| 新浪 | `43373206.0` | 股 |

差 100 倍。下游若算量比、换手率这类指标，切换数据源会得到完全不同的结果，而且**不会报错**，只是数字悄悄错了。

修法：`_SOURCES` 每项带上自己的除数，`_row_to_dict` 统一换算到「手」，并加 `volume_unit` 字段显式标注口径。验证结果：

```
东财源: volume = 433732.0
新浪源: volume = 433732.06   （43373206 股 ÷ 100）
```
